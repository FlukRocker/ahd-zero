# Chat Store, Moderation and Admin UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give members a buy/equip store page, give mods and owners delete/gag/kick/ban controls on lobby messages, and give the admin a cosmetic-authoring, grant and message-removal page — all on top of the already-merged chat backend.

**Architecture:** No new endpoints except small additions to existing payloads. The lobby and store stay server-rendered Blade + Alpine (pure logic lives in small importable JS helpers so Vitest in `node` can test it). The admin page stays Inertia + Vue. Every control is a UX hint; the server remains the only authority and its 403/422 messages are shown inline.

**Tech Stack:** Laravel 12, Blade + Alpine.js 3, Inertia + Vue 3, Vitest (node env), PHPUnit on in-memory sqlite.

**Spec:** `docs/superpowers/specs/2026-11-07-chat-lobby-design.md` (rank table L179-188, store L257-275, status codes L319-320 "the client renders all three inline", test list L365-385). Prior plan for the backend: `docs/superpowers/plans/2026-11-07-chat-lobby.md`.

## Decisions made by the controller (the user approved the picture, not these details)

- Moderation actions in the lobby: **delete, gag (fixed 10 min), kick, ban (owner+, with reason prompt)**. Not in the lobby: rank changes, ungag, unban (admin page already has ban/unban and rank).
- The client learns ranks from the server: `record()` gains a `rank` key (author's current rank string) and the bootstrap gains `myRank` (string|null). `me` stays the uuid string (earlier ruling R9).
- Store page lists only `name_*`/glow/smiley-type cosmetics — **pawn and background types are filtered out** (no visible effect yet; earlier ruling).
- Store previews use `App\Support\CosmeticStyle` on the server and the existing client `safeStyle` allow-list — never raw payload values.
- Admin cosmetic form builds the `payload` from typed fields (colour pickers/number inputs), not free-form JSON.

## Global Constraints

- Public pages: Blade + Alpine only; **never `x-html`, `innerHTML`, `insertAdjacentHTML`**; user text via `x-text`. Inertia/Vue only for `resources/js/pages/admin/*`; no `v-html`.
- Members are identified by **uuid only on the client**; `members.id` must never appear in HTML, bootstrap JSON, broadcast payloads or presence payloads. (Admin page may use ids — admin context.)
- Server routes/middleware are unchanged: member routes `auth:member` + `verified:member.verification.notice`; admin routes in the existing `['auth','verified']` dashboard group. Do not add or loosen any route.
- Bootstrap JSON stays a `<script type="application/json" id="chat-bootstrap">` with the existing `JSON_HEX_*` flags.
- **No new migration files** in this repo. Local PHP is `php`; production commands in docs use `php84`/`composer84`.
- Gate for every task: `vendor/bin/phpunit` green; `vendor/bin/phpstan analyse --memory-limit=1G --error-format=raw --no-progress` shows **no new errors versus the 6 pre-existing** (compare by file + message, ignore line numbers; no ignore comments, no silencing casts); `./vendor/bin/pint <touched php files>` (never bare pint); `pnpm test` green; eslint only on touched JS/Vue files (no `--fix` on the repo); `pnpm build` succeeds (don't commit build output).
- Pre-existing phpstan errors (do not fix): `app/Console/Commands/IndexPageViews.php` (foreach over Expression), `app/Support/AdImage.php` (x3), `app/Support/Schema.php`, `tests/Feature/NumericRouteConstraintTest.php`.
- Never `git add -A`/`.`. Never touch or stage `app/Console/Commands/IndexPageViews.php` or `public/cwv-*.jpg` (the user's uncommitted files). Commit trailer: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- **Vitest runs in `node` (`vitest.config.ts`).** Any test that needs `fetch`, `document`, `window.prompt`/`confirm` puts `// @vitest-environment happy-dom` on its first line (`happy-dom` is already a dependency) and stubs `fetch`, `window.prompt`, `window.confirm` with `vi.stubGlobal`/`vi.fn`; the CSRF token comes from a `<meta name="csrf-token" content="t">` the test appends to `document.head`. ## Review Focus

1. **A cosmetic with a hostile payload already in the DB appears in the store preview** (e.g. `red;background:url(//evil)`): the preview must fall back to the default look — only `CosmeticStyle` output reaches the browser. → Task 3.
2. **A mod's rank was demoted after the page loaded / history came from the 300 s cache**: the control is shown, the server answers 403, the page shows that message inline and does not crash or remove the line. → Task 2.
3. **Double-click on Buy or on a moderation button**: the button is disabled while the request is in flight; a second buy gets the server's "already own" 422 inline and the balance is not double-debited. → Tasks 2, 3.
4. **A member with no `chat_members` row opens the lobby and the store**: `myRank` is `member`, balance 0, no error. A guest sees the lobby with `myRank: null` and no controls. → Tasks 1, 2, 3.
5. **Admin creates a cosmetic with a bad colour or duplicate slug**: the server's 422 field errors are shown next to the form; nothing is half-created. → Task 4.
